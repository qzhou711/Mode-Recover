# Flow Matching 蒸馏 Mode Collapse：后续实验 TODO

## 1. 研究目标

当前实验已经观察到跨规模、单步 Flow Matching 蒸馏中的明显 success–diversity trade-off。下一阶段不再单纯增加训练 epochs，而是依次拆分以下潜在原因：

1. student 容量不足；
2. `16→1` 压缩跨度过大；
3. pointwise shortcut 目标压缩了噪声到模式的映射；
4. 离线训练状态与闭环访问状态不一致；
5. 蒸馏损失缺少显式的分布与多样性约束。

所有主要结论至少基于480条闭环轨迹，同时报告成功率、成功模式数、归一化模式熵、模式频数和成功/失败分色轨迹图。关键差异最终需要多随机种子复验。


### 统一评估执行规范

后续所有Avoiding闭环评估默认采用多进程环境并行，而不是单进程串行：

1. 启动前必须通过`nvidia-smi`检查当前可见且可用的GPU数量；
2. 默认每张可用GPU启动4个独立rollout worker；
3. 按全局episode编号将轨迹均匀、无重叠地划分给所有worker；
4. 每条轨迹继续使用`seed + episode_id`，保证与串行评估使用相同的随机种子集合；
5. 每个worker独立保存轨迹、成功标签、模式标签和断点；
6. 所有worker完成后统一按episode顺序合并，再计算成功率、模式数、模式熵和绘制轨迹图；
7. 若没有可用GPU，或实际可见GPU数与启动记录不一致，任务应立即失败，不静默退回单卡；
8. 日志必须记录GPU数量、worker数量、episode范围、checkpoint和模型结构。

该方案主要通过并行PyBullet环境减少CPU仿真等待；小模型单步推理本身不足以长期占满V100，因此以缩短总评估时间为目标，不以GPU利用率百分比作为唯一优化指标。

| 对照 | 成功率 | 模式数 | 模式熵 |
|---|---:|---:|---:|
| `FM-3x48-16-Full` | 92.7% | 24/24 | 0.965 |
| `FM-3x48-1-Solver` | 82.1% | 14/24 | 0.569 |

| `2×36` `FM-2x36-1-Distill-4x72` | 80.6% | 12/24 | 0.147 |

核心判据：

- 若 `3×48` 同规模蒸馏恢复接近24个模式和高熵，说明适当容量能够承载单步多模态 transport，进一步支持 capacity gap 是跨规模 collapse 的重要来源。
- 若仍明显集中到少数模式，说明即使没有 teacher–student 参数量差距，`3×48` 对单步映射的容量或当前 pointwise 蒸馏目标仍不足。
- 相对 solver-1 应同时考察成功率和熵，不能把“成功率提高但熵下降”解释为整体改进。

### TODO 5：固定状态、多噪声映射分析（已完成）

- [ ] 选取若干相同初始状态，每个状态固定采样至少1,000个初始噪声。
- [ ] teacher 与 student 使用相同噪声，并记录最终动作、轨迹和模式。
- [ ] 统计噪声到模式的占用比例、条件模式熵和 teacher/student 模式转移矩阵。
- [ ] 可视化噪声空间中不同模式的吸引域及其边界。

这是 mode collapse 最直接的机制证据：它可以显示 teacher 中通往不同模式的噪声区域，是否被 student 合并到少数输出通道。

### TODO 6：多样性保持损失对照

- [ ] 普通 pointwise shortcut 基线。
