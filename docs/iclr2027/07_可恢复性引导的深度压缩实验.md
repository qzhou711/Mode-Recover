# 可恢复性引导的深度压缩实验

更新时间：2026-08-01

## 1. 实验动机

TinySR指出，扩散Transformer的剪枝结构不应只根据静态重要性、输入输出相似度或剪枝瞬间的
loss选择，而应根据候选结构经过有限恢复训练后的任务性能，即recoverability选择。论文使用
概率mask、Dynamic Inter-block Activation与Expansion-Corrosion处理深层网络的组合爆炸。

当前Avoid Flow Matching Teacher只有4层，因此本实验没有照搬Gumbel mask搜索，而是穷举
全部四种保留3层的有序子集。这样能无近似地回答：哪一层最可删除、哪一种浅层结构最容易从
Teacher rollout中恢复闭环能力？

参考论文：`papers/TinySR_CVPR2026.pdf`。

## 2. 研究问题与目标关系

长期目标是实现demo-free、可迁移到FastWAM/DreamZero的跨架构与跨步数机器人生成策略蒸馏，
同时保持mode diversity。本实验只研究架构压缩/跨架构蒸馏的深度维度：

```text
FM-4x72-16 Full Teacher
  -> FM-3x72-16 depth-only Student
```

它不改变hidden width、attention heads和solver steps，因此不会把深度压缩、宽度压缩与步数
压缩混在一起。若该阶段成功，下一阶段才固定最佳深度mask并执行`3x72 -> 3x48`宽度压缩。

## 3. 审计后的统一协议

### 3.1 模型与初始化

| 项目 | 设置 |
|---|---|
| Teacher | `FM-4x72-16-Full`，274,826参数 |
| Student | `FM-3x72-16`，211,682参数 |
| 参数减少 | 63,144，约22.98% |
| 候选mask | keep012、keep013、keep023、keep123 |
| 初始化 | 共享模块及所选Teacher block逐元素复制 |
| 初始化审计 | 所有候选`max_abs_diff=0` |

`keep013`表示Student的三层依次复制Teacher的零索引第0、1、3层，即删除Teacher的第2层。

### 3.2 数据与训练

- 使用`strong_teacher_expanded_2400`中的成功Teacher rollout；
- 训练样本146,666个状态窗口；
- 不读取原始demonstration，不使用专家动作；
- 四组共用相同buffer、seed 42、batch顺序、优化器和scheduler；
- AdamW，学习率`3e-5`，500 epochs，每epoch最多4 batches；
- 目标为Teacher velocity MSE加弱endpoint anchor，`lambda_endpoint=0.03`；
- 保存epoch 50、100、250、500。

这一训练目标不是TinySR的LPIPS/GAN复刻：图像任务可以访问原始LR/HR配对，而本实验保持
demo-free，只使用Teacher生成监督。迁移的是“按恢复后任务性能选结构”的原则。

### 3.3 评估与预注册选择

- 每个checkpoint先做单GPU四worker Standard-120；
- 门槛为`SR>=80%`且成功轨迹覆盖`>=22/24`；
- 通过者按SR、覆盖、模式熵排序；
- 选中候选补Standard-480；
- 覆盖和熵只在成功轨迹上计算，不能替代逐mode成功率；
- Standard-120只作筛选，不用于1--3个mode的论文级细粒度结论。

审计文件：`logs/avoiding/tinysr_depth_recoverability/audit.json`。

## 6. 机制分析

### 6.1 这项结果证明了什么

1. **强Teacher知识可以在demo-free条件下完成高质量纯深度迁移。** 91.0%/24显著超过此前
   直接`4x72 -> 3x48`的约60%/22。
2. **此前主要问题不是Teacher rollout不可用。** 相同强Teacher buffer在合理浅层结构上可以
   恢复接近Teacher的闭环性能。
3. **同时压缩深度和宽度是主要混杂。** 旧Early-layer不仅删除层，还把72维投影到48维；本次
   保持72维后性能大幅恢复。
4. **层选择必须看恢复后闭环性能。** keep013与其它组合差距巨大，静态复制early layers不是
   普遍安全规则。
5. **层具有功能不对称性。** 删除第0层最有害；删除第1层也明显损害恢复；删除最后一层比删除
   第2层更差。当前Teacher的第2层最可恢复。

### 6.2 尚未证明什么

1. 目前只有一个训练seed，尚不能声明跨seed稳定；
2. Standard-480包含用于筛选的前120条episode，存在轻微选择重叠，需要独立episode suite；
3. 24/24中最少mode只有3条成功，需逐mode SR和多seed确认尾部稳定性；
4. 已补V100纯模型latency，但尚未统计MAC和机器人系统端到端wall-clock；
5. keep013的Endpoint-250一步蒸馏已补Standard-480：`91.9%/23/H=.807`；仍需多seed、独立
   suite与solver-only对照；
6. 4层网络可以穷举，尚未验证TinySR概率mask机制在深层WAM上的有效性；
7. 结果不能说明`3x48`容量不足，因为`FM-3x48-16-Full`已达到92.7%/24；真正未解决的是
   demo-free宽度知识迁移。

## 7. 后续实验基线与执行顺序

### P0：固定深度结论

- [ ] keep013 epoch-500补训练seed 43/44；
- [ ] 使用不与Standard-120重叠的独立480条episode确认；
- [ ] 输出逐mode频次、逐mode SR、参数量、MAC和实测延迟；
- [ ] 若独立评估仍约`SR>=88%、Coverage>=22`，正式固定keep013。

### P1：单独解决宽度压缩

固定`FM-3x72-16 keep013`为新Teacher，执行`3x72 -> 3x48`，不再改变深度mask、heads以外的
必要维度或solver steps。四卡优先比较：

1. activation-aware/PCA width projection＋统一Repair；
2. MiniLMv2 Q/K/V relation width transfer；
3. Teacher Assistant：`3x72 -> 3x60 -> 3x48`；
4. recoverability-guided width channel/subspace选择。

共同门槛为`Standard-120 SR>=80%、Coverage>=22`，通过者补独立Standard-480。必须同时报告
相对3x72 Teacher的SR retention、mode retention和熵变化。

### P2：完整跨架构蒸馏与步数蒸馏

只有3x48-16通过架构压缩门槛后，才执行Natural Replay或保模态CTM的`16 -> 1`步数蒸馏，分别
报告深度、宽度和步数三阶段损失。不得直接从4x72联合压缩到3x48-1后再反推原因。

### P3：深层WAM迁移

在D3IL确认recoverability criterion后，FastWAM/DreamZero等深层Transformer才需要
TinySR式blockwise probability、Dynamic Inter-block Activation与Expansion-Corrosion。
WAM的mask选择目标必须加入动作闭环成功、条件多样性和world-action一致性，不能只复用图像
LPIPS/L1。

## 9. keep013之后的一步蒸馏与联合加速

在保持3x72结构不变的条件下，比较Endpoint fidelity与Boundary-CTM＋DSM的16→1步蒸馏。
训练继续使用无原始示范的Teacher rollout状态，并在线查询keep013 Teacher。Standard-120最佳
为Endpoint epoch-250：`111/120=92.5%`、`21/24`、`H=0.807`；正式Standard-480为
`441/480=91.9%`、`23/24`、`H=0.807`。Boundary-CTM最佳SR为`81.7%`，Standard-120
覆盖最高只有12种。因此当前深度压缩checkpoint能够支持有效一步蒸馏，但一步目标仍造成一个尾部
模式损失和明显的频率不均衡。

统一V100、batch=1、100 warmup、1000 repeats的纯模型latency为：原始4x72-16 Full
`65.93 ms`，3x72-16 keep013 `51.19 ms`，3x72-1 Endpoint-250 `2.22 ms`。联合压缩相对
原始Full约加速29.7倍，其中深度压缩贡献1.29倍，主要收益来自步数压缩。

该结果不改变宽度压缩主线：3x72-1是验证“成功架构压缩能否继续接一步蒸馏”的中间成果，
最终仍需解决3x72→更小算子/宽度Student。完整一步协议、checkpoint曲线和结论边界见
`03_一致性蒸馏与CTM实验.md`第15节。

## 10. 无标签可恢复性代理与门控优化审计（2026-08-04）

### 10.1 离散硬结构上的代理资格审查

为使层选择迁移到没有D3IL 24-mode标签的FastWAM，固定Teacher状态和同一噪声，仅使用
Teacher-relative信号评价四个硬mask。代理包括Endpoint均值/CVaR、velocity均值/CVaR、同状态
多噪声短轨迹配对误差以及Teacher→Student coverage和Student→Teacher precision。训练与评价均
不访问原始示范或专家动作，mode标签不进入代理。

在epoch-0和统一50-epoch短Repair后，除单独的Gram项外，主要代理均给出正确排序：

`keep013 < keep012 < keep023 < keep123`（误差越低越好）。

这与500-epoch闭环SR排序`91.7% > 75.0% > 65.0% > 27.5%`一致。Gram距离排序不稳定，不能
单独作为门控目标。

### 10.2 Hard Top-3共享超网负结果

随后从四层等logit（每层初始概率相同）出发，统一采用Hard Top-3前向和straight-through反向，
比较四种outer目标。注意：本轮**没有使用SVD概率初始化**。

| Outer目标 | 250 epochs最终mask | 最终layer logits（0/1/2/3） |
|---|---|---|
| mean Endpoint | keep012 | 0.159 / 0.368 / 0.419 / -0.073 |
| Endpoint-CVaR | keep012 | 0.124 / 0.318 / 0.361 / -0.050 |
| CVaR＋短轨迹 | keep012 | 0.069 / 0.372 / 0.358 / -0.112 |
| CVaR＋短轨迹＋双向集合距离 | keep012 | 0.070 / 0.387 / 0.398 / -0.122 |

四组均错误压低第3层并选择keep012。由于等概率初始化已经排除了SVD先验，本负结果定位到优化
机制：共享权重产生候选间不公平共适应；hard前向/soft反向存在离散化梯度偏差；交替更新没有对
`w_after_repair(g)`关于gate求超梯度，因此不是真正优化`J_after_repair`。结论不是代理失效，而是
shared-supernet straight-through不能可靠地优化该代理。

### 10.3 独立短Repair能否预测长期可恢复性

四个硬mask从相同Teacher映射独立初始化，使用全部Teacher rollout；不使用成功筛选、奖励、mode
或原始示范。episode-id模10余2的轨迹严格留作held-out评价。结果如下（Endpoint-CVaR，越低越好）：

| Repair预算 | keep013 | keep012 | keep023 | keep123 |
|---:|---:|---:|---:|---:|
| 5 | **0.194** | 0.341 | 0.771 | 3.602 |
| 10 | **0.171** | 0.267 | 0.697 | 3.265 |
| 25 | **0.148** | 0.175 | 0.572 | 2.967 |
| 50 | **0.140** | 0.151 | 0.525 | 2.882 |

velocity-CVaR、短轨迹配对误差和双向集合距离在全部四个预算上也给出完全相同排序。由此确认：
5 epochs独立短Repair已经足以作为当前任务的`J_after_repair`近似。四mask完整计算仅作为D3IL校准
真值，不能冒充可扩展搜索算法。

### 10.4 下一步：等概率离散架构分布

下一阶段不再使用SVD先验，也不再用共享soft超网。对“删除哪一层”学习分类分布
`q=softmax(alpha/tau)`，四个候选从等概率开始；每轮采样两个真实硬结构，从相同Teacher映射执行
相同5-epoch独立短Repair，再以paired held-out相对可恢复性更新`alpha`。前期保留探索概率，后期
温度退火和低熵约束使分布接近one-hot。验收为至少3/4独立seed选择keep013且最终概率超过0.8。
