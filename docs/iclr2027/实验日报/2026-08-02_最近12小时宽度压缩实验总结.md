# 2026-08-02 最近12小时宽度压缩实验总结

记录窗口：截至2026-08-02 13:40 EDT前约12小时。本文只汇总此前尚未正式写入ICLR2027
文档的实验；所有闭环结果均来自日志中的原始`metrics.json`。除特别说明外均为单seed
Standard-120筛选结果，不能直接作为论文级稳定性结论。

## 1. 目标与统一协议

长期目标是在不访问原始示范的条件下，将大、多步机器人/WAM生成策略蒸馏为异构、小容量、
少步Student，同时保持闭环成功率和条件多模态行为。最近12小时只研究**架构压缩/跨架构蒸馏的宽度/算子
压缩阶段**，不改变16步求解器，也没有执行CTM或其它步数蒸馏。

统一起点为`FM-3x72-16 keep013`：211,682参数，Standard-480为`437/480=91.0%`、
`24/24`、`H=0.929`。训练监督来自同一个成功Teacher rollout buffer；当前算子实验使用
140,867个状态/噪声/endpoint样本，不读取原始demonstration或专家动作。Repair统一以Teacher
velocity MSE加弱endpoint anchor（权重0.03）为主，seed 42。闭环评估采用每模型单GPU、
每GPU四worker。

预注册筛选门槛为`SR>=80%且Coverage>=22/24`。只有过门槛的checkpoint才值得补独立
Standard-480和多seed。模式熵只作辅助指标。

## 2. Head数量与残差宽度的机制解耦

### 2.1 实验问题

旧`3x72 -> 3x48`会同时把hidden width从72降到48、attention heads从4降到3。该实验通过
四路对照判断collapse究竟来自head数量变化，还是共享残差坐标被压缩。

| 方法 | Student | 主要变化 | 初始化 SR/覆盖/H | epoch-250 SR/覆盖/H |
|---|---|---|---:|---:|
| Head-only | `3x72, 3 heads` | 只将4 heads改为3，保留72维残差 | 59.2% / 20 / 0.837 | **90.8% / 23 / 0.911** |
| Per-head coordinate | `3x48, 4 heads` | 每个head独立18→12选坐标 | 3.3% / 2 / 0.218 | 49.2% / 10 / 0.507 |
| Per-head PCA | `3x48, 4 heads` | 每个head独立18→12 PCA | 2.5% / 1 / 0.000 | 47.5% / 4 / 0.171 |
| Global PCA control | `3x48, 3 heads` | 全局72→48 PCA | 19.2% / 1 / 0.000 | 78.3% / 4 / 0.083 |

### 2.2 结论

1. **减少一个attention head不是主要瓶颈。** Head-only在保留72维残差时，经250轮Repair达到
   90.8%/23，接近3x72 Teacher，并通过80/22筛选门槛。
2. **真正敏感的是72→48共享残差坐标压缩。** 即使保留4个head身份，per-head映射仍然严重
   损失SR和模式；因此“只要保留head数量即可”的解释被否定。
3. Global PCA可恢复较高SR但只有4种模式，说明点对点Repair能找到少数安全吸引域，却没有
   恢复原有noise-to-mode分区。
4. 以上是Standard-120单seed结果；Head-only是机制阳性对照，不是最终宽度压缩方案，因为其
   参数规模仍接近3x72。

原始产物：`logs/avoiding/head_width_mechanism_audit/`。

## 3. 渐进宽度、PPCL适配器与FFN-only压缩

### 3.1 设计

在确认残差宽度是核心敏感因素后，比较两类策略：

- 改善72→48的迁移路径：渐进PCA `72→60→48`、训练期PPCL式线性对齐adapter；
- 不压缩残差72，只压缩FFN内部宽度`288→36`：activation energy选通道、weight saliency选通道。

| 方法 | 初始化 | epoch-50 | epoch-250 | epoch-500 |
|---|---:|---:|---:|---:|
| Progressive PCA `72→60→48` | 1.7% / 1 / 0.000 | — | — | **85.0% / 4 / 0.086** |
| PPCL adapter `72→48` | 13.3% / 1 / 0.000 | 7.5% / 2 / 0.110 | 67.5% / 5 / 0.165 | 66.7% / 2 / 0.111 |
| FFN activation `288→36` | 75.8% / 2 / 0.019 | 42.5% / 7 / 0.330 | 38.3% / 14 / 0.729 | **46.7% / 15 / 0.763** |
| FFN weight saliency `288→36` | 85.8% / 1 / 0.000 | 18.3% / 4 / 0.292 | 40.8% / 8 / 0.417 | 45.0% / 5 / 0.366 |

### 3.2 结论

1. **渐进宽度和PPCL没有解决mode collapse。** Progressive PCA达到85% SR却只有4 modes；
   PPCL最高67.5%/5。容量gap课程或训练期对齐本身不足以保存noise-to-mode几何。
2. **残差72不是唯一承载模式路由的部位。** FFN activation压缩随训练把覆盖从2提高到15、熵
   提高到0.763，但SR降到46.7%；说明FFN内部也参与模式选择和可执行控制。
3. **初始化高SR不等于跨架构迁移成功。** FFN weight saliency初始85.8%但仅1 mode，是典型的
   高SR单吸引域；不能按SR单独选择checkpoint。
4. FFN activation相对weight saliency更能恢复多样性，提示Teacher rollout上的激活几何比静态
   权重幅值更贴近任务相关子空间，但它仍未达到80/22门槛。
5. 极端FFN压缩`288→36`（保留12.5%中间通道）过于集中地破坏一个子系统，形成“高覆盖低
   成功”的另一端Pareto点；这促使下一轮改为跨attention和FFN分布式压缩。

原始产物：`logs/avoiding/width_transfer_mechanisms/`。

## 4. 残差保持的低秩算子压缩（正在评估）

### 4.1 机制假设

不再寻找一个固定的72→48全局投影，而是始终保留3层、72维残差、4 heads和16步，在每个
Q/K/V/proj及FFN线性算子内部做低秩分解。假设是：只要不破坏共享残差坐标系，并将参数削减
分散到多个算子，noise-to-mode routing可能比全局width projection或FFN-only极端剪枝更稳定。

| Lane | 参数量 | 相对3x72参数保留 | 配置 |
|---|---:|---:|---|
| Uniform SVD | 97,634 | 46.1% | attention统一rank 32；FFN两层rank 8；权重SVD初始化 |
| Uniform activation | 97,634 | 46.1% | 相同rank；Teacher rollout activation加权初始化 |
| Routing-aware | 93,314 | 44.1% | Q/K rank 40，V/proj rank 24，FFN rank 6 |
| Hybrid balanced | 107,426 | 50.7% | FFN 288→96；Q/K rank 32，V/proj rank 16 |

四组均已完成500 epochs。最后一轮训练标量如下，但**训练loss不能替代闭环评估**：

|---|---:|---:|---:|

| Uniform activation | 0.3273 | 0.3235 | 0.1264 |
| Routing-aware | 0.5287 | 0.5207 | 0.2687 |
| Hybrid balanced | **0.0928** | **0.0916** | **0.0399** |

## 5. 最近12小时形成的因果链

当前证据把“宽度压缩失败”进一步拆解为：

1. 纯深度压缩可行：3x72 keep013达到91.0%/24；
2. 单纯减少head数量也可恢复：3x72/3-head达到90.8%/23（Std120）；
3. 一旦压缩共享残差72→48，不论全局PCA还是逐head投影，都容易进入高SR低覆盖捷径；
4. 完全保留残差、只极端压缩FFN又会造成高覆盖低SR，证明功能与模式路由分布在多个算子；
5. 因而最有信息增益的下一步不是继续扫静态投影或增加epoch，而是检验“保留残差坐标、分布式
   压缩算子秩”的假设。当前低秩四路实验正对此作直接检验。

这仍然只是D3IL上的跨架构蒸馏机制证据。若低秩方案通过门槛，下一步才补Standard-480、多seed、
MAC/延迟，并在验收后的16步Student上研究16→1步数蒸馏。若全部失败，则应把结论收紧为：
当前pointwise velocity+endpoint Repair不能识别压缩后完整的noise-to-mode映射，而不是简单认为
低秩容量不足。
