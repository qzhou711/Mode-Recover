# 从深度压缩到一步蒸馏：面向多模态机器人Flow Policy的无示范压缩技术报告

版本：2026-08-03  
任务：D3IL Avoiding，24种几何路径模式  
状态：论文方法与实验章节底稿；核心正式结果为单训练seed，统计性结论仍需多seed确认

## 摘要

本文研究如何同时降低机器人生成策略的网络深度和生成步数，并在闭环执行中保持行为多模态。
与只报告平均成功率和推理速度的压缩工作不同，我们将成功率（SR）、成功模式覆盖、逐模式成功率和
模式熵共同作为验收指标，并将压缩分成两个可独立审计的阶段：

1. **架构压缩/跨架构蒸馏**：将16步`FM-4x72` Teacher压缩为16步`FM-3x72` Student；
2. **步数蒸馏**：固定已经通过架构验收的`FM-3x72`，再将16步求解压缩为一步生成。

架构阶段不使用静态权重重要性直接决定删除层，而是穷举全部四个保留三层的有序子网，对每个子网
执行相同的Teacher-rollout repair，并以恢复后的闭环成功率和模式覆盖选择结构。最优`keep013`
删除Teacher的第2层，参数由274,826降至211,682（减少23.0%），Standard-480达到
`437/480=91.0%`、`24/24 modes`、`H=0.929`；完整Teacher为`95.8%/24/H=0.945`。

在此基础上，我们比较一步Endpoint fidelity和Boundary-CTM＋DSM。Endpoint方法直接保持配对
`(state, noise)`对应的16步Teacher终点，epoch-250的Standard-480达到
`441/480=91.9%`、`23/24 modes`、`H=0.807`。相比之下，Boundary-CTM在Standard-120上的
最佳成功率为81.7%，模式覆盖随训练从12降至8，显示自举trajectory consistency会在该设置下
合并noise-to-mode basin。V100、batch=1的平均纯模型延迟从完整Teacher的65.93 ms降至深度压缩
模型的51.19 ms，再降至一步模型的2.22 ms，联合加速29.7倍。

结果支持以下阶段性结论：闭环可恢复性是比静态权重重要性更可靠的层选择准则；一个高质量、多模态
的架构压缩起点能够接受进一步的一步蒸馏；但平均成功率相近并不代表模式分布被完整保存，步数蒸馏
仍需针对条件分布和noise-to-mode几何施加约束。

## 1. 问题定义

### 1.1 长期目标

长期目标不是只为D3IL设计一个特例，而是构建可迁移到FastWAM、DreamZero等真实World Action
Model的压缩框架：在不访问Teacher原始示范数据的条件下，对不同架构的生成式机器人策略同时完成
容量压缩和求解步数压缩，并尽可能保持任务成功率与行为分布。

本文中的“无示范”限定为：**压缩、repair和步数蒸馏阶段不读取原始demonstration或专家动作**。
Teacher自身最初由示范训练得到，因此不能声称整个模型生命周期从未接触示范。

### 1.2 为什么需要分阶段

总推理成本可近似写为：

```text
latency ≈ cost_per_network_call(architecture) × number_of_solver_calls
```

因此存在两个不同问题：

- **架构压缩（architecture compression）**降低单次网络调用成本；
- **步数蒸馏（step distillation）**降低调用次数。

若一次同时改变架构和步数，性能下降后无法判断是表示容量、初始化、repair、闭环状态漂移还是一步
目标造成。本文要求每个阶段先通过闭环验收，再进入下一阶段。

### 1.3 多模态评价

Avoiding任务存在24种由障碍物上下绕行组合形成的成功路径模式。我们报告：

- `SR = 成功轨迹数 / 总轨迹数`；
- `Coverage = 至少出现一次成功轨迹的模式数 / 24`；
- `H_norm = -Σ_m p_m log(p_m) / log(24)`，其中`p_m`只由成功轨迹估计；
- 逐模式成功率，作为判断稀有模式是否真正可执行的主要诊断；
- V100、batch=1、固定warmup/repeats的CUDA latency。

模式熵只作辅助：较高熵可能只是已覆盖少数模式之间更均匀，不能代替coverage或逐模式成功率。

## 2. 基础Flow Matching策略

输入是当前观测状态序列`s`、初始动作噪声`x_0 ~ N(0,I)`以及连续时间`t∈[0,1]`。网络
`v_theta(x_t,t,s)`预测条件速度场，并通过16步Heun积分得到动作终点：

```text
x_1 = ODESolve(v_theta, x_0, s, t: 0 -> 1, N=16).
```

完整Teacher为4层Transformer、hidden size 72、4 attention heads：

```text
FM-4x72-16 Full
parameters = 274,826
Standard-480 = 460/480 = 95.8%, Coverage 24/24, H=0.945
```

Teacher的随机噪声不仅提供局部扰动，还决定最终进入哪个路径吸引域。因此压缩必须保持条件
`noise -> trajectory mode`映射，而不只是平均动作误差。

## 3. 阶段一：可恢复性引导的深度压缩

### 3.1 结构搜索空间

Teacher有4个按顺序排列的Transformer block。目标Student保留3层，因此完整搜索空间只有：

```text
keep012: 保留Teacher层0,1,2，删除层3
keep013: 保留Teacher层0,1,3，删除层2
keep023: 保留Teacher层0,2,3，删除层1
keep123: 保留Teacher层1,2,3，删除层0
```

共享embedding、output head、LayerNorm和被选中的block均从Teacher逐元素精确复制。初始化代码对
所有映射参数执行bitwise差异审计，要求最大差异为0。

### 3.2 为什么不直接按静态重要性剪枝

层权重范数、SVD重构误差或局部feature误差只能描述静态算子信息量，不能直接回答：删除该层后，
Student经过有限repair是否还能在闭环中恢复Teacher的mode routing和纠错能力。

因此我们定义结构质量为**删除后可恢复性**，而不是删除瞬间的开环误差。每个候选结构接受完全相同
的Teacher、rollout buffer、训练更新数、优化器和评估suite，最后由恢复后的闭环指标选择。

### 3.3 无示范Teacher rollout buffer

冻结`FM-4x72-16 Full`在环境中执行，保存：

```text
(episode_id, state, initial_noise, teacher_endpoint, success)
```

repair只使用成功Teacher rollout对应的状态窗口、原生噪声和Teacher终点；不读取原始示范文件，
也不调用专家动作。当前深度实验来自2400条Teacher rollout，筛选后包含约146,666个训练窗口。
保持`state-noise-endpoint`身份配对很重要，否则会把不同mode的噪声错误配到同一目标上。

### 3.4 Repair目标

对一个batch随机采样`t∈[0.02,0.98]`。先用冻结Teacher从同一噪声积分到`t`：

```text
x_t^T = ODESolve(v_T, x_0, s, 0 -> t)
```

再在Teacher访问的状态上匹配瞬时速度：

```text
L_vel = MSE(v_S(x_t^T,t,s), v_T(x_t^T,t,s)).
```

同时将Student从原生噪声可微地积分16步，与buffer中的Teacher终点对齐：

```text
x_1^S = DiffODESolve(v_S, x_0, s, 0 -> 1, N=16)
L_end = MSE(x_1^S, x_1^T)
L_repair = L_vel + 0.03 L_end.
```

`L_vel`传递局部动力学，`L_end`抑制局部误差沿16步累计后的终点漂移。所有候选训练500 epochs，
每epoch最多4个batch，batch size 256，AdamW，初始学习率`3e-5`，cosine decay，EMA 0.995。

### 3.5 筛选协议

保存epoch 50、100、250、500。Standard-120只用于低成本筛选：

```text
Go gate: SR >= 80% AND Coverage >= 22
```

通过者按闭环SR、coverage和熵选择，再补Standard-480。Standard-120不用于最终细粒度比较。

### 3.6 四个深度子网结果

| Mask | 最佳/代表epoch | Standard-120 SR | Coverage | H | 机制解释 |
|---|---:|---:|---:|---:|---|
| keep012 | 50 | 82.5% | 19 | 0.825 | 可执行性尚可，模式恢复不足；后期SR下降 |
| **keep013** | **500** | **91.7%** | **23** | **0.921** | 唯一持续通过联合门槛，选中 |
| keep023 | 500 | 65.0% | 18 | 0.790 | 删除早期层后功能恢复有限 |
| keep123 | 500 | 27.5% | 8 | 0.604 | 删除第0层严重破坏输入/早期路由 |

keep013的正式结果为：

| 模型 | 参数量 | Standard-480 SR | Coverage | H |
|---|---:|---:|---:|---:|
| FM-4x72-16 Full | 274,826 | 460/480，95.8% | 24/24 | 0.945 |
| **FM-3x72-16 keep013** | **211,682** | **437/480，91.0%** | **24/24** | **0.929** |

参数减少`(274826-211682)/274826 = 23.0%`。SR下降4.8个百分点，但24种成功模式全部保留，
说明该阶段实现了“容量降低、支持集不坍缩”。

### 3.7 LightDP-style层选择对照

为对照已有端侧Diffusion Transformer压缩路线，我们实现SVD重构误差初始化＋Gumbel-Sigmoid
可学习门控：先在4层超网上联合学习250 epochs，再保留概率最高的3层，并执行相同500-epoch
repair。该实现使用Flow和Teacher rollout，因此是受控的`LightDP-style`对照，不是原论文基于
demonstration和DDPM的严格复现。

SVD初始分数与最终门控均选择`keep012`，而不是闭环最优的`keep013`：

| 方法 | 选择 | 最佳Standard-120 SR | Coverage | H |
|---|---|---:|---:|---:|
| LightDP-style SVD＋learned gate | keep012 | 81.7% | 23 | 0.928 |
| 闭环可恢复性选择 | keep013 | 91.7% | 23 | 0.921 |

两者coverage接近，但LightDP-style的成功率低约10个百分点。这说明静态权重重要性或平均
Teacher fidelity可能保留“多种输出形态”，却未识别使这些模式闭环成功执行所需的层。该对照目前
只有Standard-120，因未达到预设`SR>=88%`门槛而未补Standard-480，不能作精细统计排序。

## 4. 阶段二：固定架构的一步蒸馏

### 4.1 因果隔离

步数阶段固定以下所有变量：

```text
Teacher architecture = Student architecture = FM-3x72
Teacher = keep013 epoch-500, 16-step Heun
Student initialization = exact Teacher checkpoint
training states/noises = same teacher-rollout buffer
seed, optimizer, batch size, updates = paired
only changed factor = one-step objective
```

因此，若16步keep013保持24种模式而一步Student坍缩，问题可定位到步数蒸馏目标或一步推理，而
不是Student容量。

### 4.2 Boundary一步参数化

令Student网络预测速度`v_S(x_t,t,s,stop)`，一步到数据边界的映射为：

```text
F_S(x_t,t -> 1,s) = x_t + (1-t) v_S(x_t,t,s,stop=1).
```

当`t=0`时：

```text
x_hat_1 = x_0 + v_S(x_0,0,s,1).
```

所有一步模型必须用`boundary_transition(0 -> 1)`评估；若错误使用普通一步ODE积分，训练目标和
推理协议不一致，结果无效。

### 4.3 方法A：配对Endpoint fidelity

对buffer中的原生`(s,x_0)`在线查询实际keep013 Teacher的16步终点：

```text
x_1^T = ODESolve(v_T, x_0, s, 0 -> 1, N=16)
x_hat_1^S = F_S(x_0,0 -> 1,s)
L_endpoint = pseudo_huber(x_hat_1^S, x_1^T; delta=0.01).
```

它直接保持同一个噪声样本的Teacher动作结果，因此属于paired fidelity/shortcut distillation。
其优势是目标稳定且可识别：collapsed Student不能仅靠匹配平均轨迹达到所有配对终点。局限是它只
约束`0 -> 1`端点，不显式学习任意`time -> stop_time`轨迹一致性。

### 4.4 方法B：Boundary-CTM＋DSM

随机选择离散时间`i`和更晚的`s`，其中`0 <= i < s <= 16`且至少跨两个区间。CTM构造Online
Student预测与EMA Target参考：

```text
L_ctm = pseudo_huber(F_S(x_i, i -> s, state),
                     stop_gradient(F_EMA(reference_state, ..., state))).
```

再加入到数据边界的DSM/endpoint约束：

```text
L_dsm = pseudo_huber(F_S(x_i, i -> 1, state), x_1^T)
L_total = L_ctm + 0.1 L_dsm.
```

Online Student更新后，Target以`EMA=0.995`更新。该方法试图学习trajectory consistency，但参考
目标部分来自Student自身的EMA，因此存在自举偏差：如果部分noise basin先被合并，EMA会把该合并
继续作为一致目标传播。

### 4.5 训练与checkpoint选择

两种方法均训练500 epochs，batch size 256，每epoch最多4个batch，Adam学习率`1e-4`，cosine
decay至`1e-6`。保存epoch 100、250、500，并以Standard-120选择闭环checkpoint；不能仅按训练
loss最低选择，因为Endpoint训练loss的best epoch为385，而闭环多模态最好的已保存点是250。

### 4.6 Standard-120筛选结果

| 方法 | Epoch | SR | Coverage | H |
|---|---:|---:|---:|---:|
| Endpoint | 100 | **94.2%** | 15 | 0.689 |
| **Endpoint** | **250** | **92.5%** | **21** | **0.807** |
| Endpoint | 500 | 90.0% | 19 | 0.762 |
| Boundary-CTM＋DSM | 100 | 65.8% | **12** | **0.465** |
| Boundary-CTM＋DSM | 250 | **81.7%** | 9 | 0.331 |
| Boundary-CTM＋DSM | 500 | **81.7%** | 8 | 0.348 |

Endpoint出现“早期SR高但覆盖低”的现象，表明平均准确率先恢复，稀有noise basin随后逐渐恢复；训练
过久又损失部分覆盖。CTM的SR有所恢复，但覆盖随训练持续下降，属于高成功倾向与mode merging并存。

### 4.7 Endpoint-250正式结果

| 模型 | 架构/步数 | Standard-480 SR | Coverage | H |
|---|---|---:|---:|---:|
| Full Teacher | 4x72 / 16 | 460/480，95.8% | 24/24 | 0.945 |
| Depth-compressed Teacher | 3x72 / 16 | 437/480，91.0% | 24/24 | 0.929 |
| **Endpoint Student** | **3x72 / 1** | **441/480，91.9%** | **23/24** | **0.807** |

一步Student相对其16步Teacher：

- SR增加0.8个百分点，属于单suite/单seed下的小差异，不能宣称真实提升；
- coverage从24降至23，支持集只损失1种；
- 熵从0.929降至0.807，说明主要问题是模式频率变得更不均衡，而不是严重支持集坍缩；
- 相对原始Full，SR低约4.0个百分点，coverage少1种。

当前正式结果足以证明“高质量架构压缩起点可以进一步一步化而不发生严重mode collapse”，但不足以
宣称Endpoint普遍优于CTM：Boundary-CTM尚缺同规模Standard-480和多seed确认，同时两者目标类型
不同。

## 5. 计算效率

延迟在同一Tesla V100、batch size 1、100次warmup、1000次重复下测得：

| 模型 | 参数量 | 调用步数 | Mean | Median | P95 | 相对Full加速 |
|---|---:|---:|---:|---:|---:|---:|
| FM-4x72-16 Full | 274,826 | 16 | 65.93 ms | 65.29 ms | 69.57 ms | 1.00x |
| FM-3x72-16 keep013 | 211,682 | 16 | 51.19 ms | 51.16 ms | 51.39 ms | 1.29x |
| **FM-3x72-1 Endpoint-250** | **211,682** | **1** | **2.22 ms** | **2.19 ms** | **2.38 ms** | **29.7x** |

深度压缩单独带来约22.4%的延迟下降，明显小于理论25%的层数下降，因为embedding、head和其他固定
开销不随block数缩放。一步化消除了绝大部分重复调用，是联合加速的主要来源。

## 6. 完整算法

### 6.1 阶段一：闭环可恢复性深度压缩

```text
Input:
  frozen 4-layer Teacher T
  successful Teacher rollout buffer B
  candidate ordered layer subsets M = {012,013,023,123}

for mask m in M:
  construct 3-layer Student S_m
  exactly copy shared tensors and Teacher blocks indexed by m
  for epoch = 1..500:
    sample paired (state, noise, teacher_endpoint) from B
    sample time t
    obtain Teacher intermediate x_t and velocity v_T
    minimize MSE(v_S, v_T) + 0.03 MSE(endpoint_S, endpoint_T)
    update EMA
  evaluate checkpoints on Standard-120 closed loop

select mask/checkpoint by SR + coverage gate
confirm selected model with Standard-480
Output: FM-3x72-16 keep013
```

### 6.2 阶段二：一步Endpoint蒸馏

```text
Input:
  validated FM-3x72-16 keep013 Teacher T'
  paired Teacher rollout states and noises B

initialize one-step Student S exactly from T'
for epoch = 1..500:
  sample paired (state, noise) from B
  query endpoint_T = Integrate16(T', noise, state)
  predict endpoint_S = BoundaryTransition(S, noise, 0 -> 1, state)
  minimize pseudo_huber(endpoint_S, endpoint_T)
  update EMA target

screen checkpoints at 100/250/500 on Standard-120
confirm selected epoch-250 with Standard-480
Output: FM-3x72-1 Endpoint-250
```

## 7. 机制分析

### 7.1 深度不是均匀冗余的

`keep013`远优于`keep123`，说明早期层承担不可替代的输入变换或noise-conditioned routing；
`keep013`又优于`keep012`，说明最后一层对把多种候选行为修正为可执行动作非常重要。层作用不能由
“越早越重要”或“权重越难低秩逼近越重要”概括。

### 7.2 Coverage和SR描述不同失效

LightDP-style达到23种模式但SR只有81.7%，表明模式形态仍存在，却有相当比例无法闭环完成；这更像
执行稳定性损失。Endpoint-250达到91.9%和23种模式，但熵明显下降，表明主要剩余问题是模式概率
质量重新分配。两种失效需要不同干预。

### 7.3 为什么Endpoint优于当前CTM

Endpoint对每个原生noise保存确定的Teacher目标，直接限制noise basin被平均合并。当前CTM使用EMA
Student构造部分trajectory reference，优化目标可以在多个noise被映射到同一吸引域时仍取得较低的
局部一致性损失。DSM权重0.1不足以完全抵消这种自举收缩。

这不是“trajectory consistency一定不行”的普遍结论，而是说明当前受限容量、有限buffer和当前
采样协议下，稳定的Teacher配对目标比自举目标更可靠。

### 7.4 两阶段解耦的价值

若直接将4x72-16压成3x72-1，最终少1种模式时无法知道是哪一步造成。当前结果清楚定位：

```text
Full 4x72-16:        24 modes
Depth 3x72-16:       24 modes  <- 架构阶段没有丢支持集
Endpoint 3x72-1:     23 modes  <- 支持集损失发生在步数阶段
Boundary-CTM 3x72-1: 8-12 modes (Std120) <- 目标选择强烈影响坍缩
```

因此下一阶段应优先改进步数目标中的模式概率保持，而不是重新质疑3x72容量或盲目增加深度repair轮数。

## 8. 与LightDP的关系和论文定位

LightDP同样组合架构压缩和步数蒸馏，是最接近本文工程路线的外部工作之一。但其核心目标是端侧延迟
和平均任务成功率：通过SVD初始化的可学习层门控压缩Transformer，再用DDIM consistency
distillation减少去噪步数。其训练访问原始demonstration，且没有报告任务内部mode coverage。

本文不能把“删层”或“两阶段加速”本身作为原创点。更有辨识度的贡献是：

1. 将压缩目标从平均fidelity扩展到闭环mode preservation；
2. 用删除后闭环可恢复性而非静态权重重要性选择层；
3. 通过阶段化实验定位mode collapse来自架构阶段还是步数阶段；
4. 在无原始示范的Teacher rollout协议下实现压缩；
5. 揭示高coverage/低SR与高SR/低entropy是两种不同的压缩失效。

---

## 9. 证据边界与局限

1. **单训练seed**：keep013和Endpoint-250的Standard-480目前均主要来自seed 42；需要训练seed
   43/44及配对suite报告均值、方差和逐模式置信区间。
2. **CTM证据等级较低**：当前CTM只有Standard-120，足以筛掉明显坍缩配置，但不能进行精细的
   480级统计比较。
3. **Checkpoint选择存在闭环开销**：当前必须评估多个epoch才能发现epoch-250；训练loss最低并不
   等于模式最优。需要构建低成本mode-aware validation proxy。
4. **任务规模有限**：4层选3层可穷举，真实WAM不能穷举所有子网；需要把闭环可恢复性转化为可学习
   的门控信号或渐进式层选择。
5. **24 modes是可见标签**：真实机器人/WAM通常没有人工mode字典，需要无标签trajectory embedding、
   稳定聚类或条件分布距离。
6. **无示范不等于无Teacher交互**：当前需要Teacher rollout和在线endpoint查询；后续必须报告查询
   预算、buffer规模和Teacher访问成本。

## 10. 下一步实验

### P0：补齐论文级统计证据

- keep013训练seed 43/44，各做Standard-480；
- Endpoint-250训练seed 43/44，使用配对episode/noise Standard-480；
- 输出逐模式成功率、mode frequency、均值±标准差和bootstrap置信区间；
- 补3x72一步solver-only，隔离“仅减少求解步数”和“经过蒸馏”的差异。

### P1：模式保持的一步目标

以Endpoint为稳定主目标，而非从当前CTM重新开始：

```text
L = L_paired_endpoint
  + lambda_traj * L_short_horizon_distribution
  + lambda_rel * L_same_state_multi_noise_relation.
```

约束必须使用原生rollout的`state-noise-trajectory`配对，并在同一state下比较多个noise的相对几何；
验收目标是在SR不低于90%的条件下，从23/24恢复到稳定24/24并提高模式熵。

### P2：把可恢复性用于可扩展层门控

改造LightDP-style门控，使层得分不再只来自SVD和开环fidelity，而是加入短闭环Teacher rollout后的
恢复损失、Student-induced state误差和mode-aware关系信号。若门控能从`keep012`纠正到`keep013`，
说明闭环可恢复性可以作为更深WAM的可扩展结构搜索准则。

### P3：迁移到真实WAM

在FastWAM/DreamZero上保持相同三段审计：

```text
validated full Teacher
  -> validated architecture-compressed multi-step Student
  -> validated few/one-step Student
```

用trajectory encoder得到无标签行为簇，并同时报告任务成功、行为覆盖、分布距离、延迟、参数量、显存和
Teacher查询预算。

## 11. 当前可支持的论文级结论

可以支持：

- 在D3IL Avoiding上，闭环可恢复性引导的深度压缩能将4x72压成3x72，同时在Standard-480保持
  24/24成功模式；
- 静态SVD＋可学习门控选择与闭环最优层子集不一致，且闭环SR明显较低；
- 在通过架构验收的3x72模型上，配对Endpoint一步蒸馏达到91.9% SR和23/24模式，并相对原始
  4x72-16实现29.7倍纯模型加速；
- 当前Boundary-CTM＋DSM在Standard-120出现显著模式合并，说明步数目标是独立的坍缩来源。

尚不能支持：

- 不能宣称Endpoint在所有机器人策略上普遍优于CTM；
- 不能宣称29.7倍是端到端机器人系统加速；它是同GPU上的纯生成模型延迟；
- 不能宣称结果已跨seed统计稳定；
- 不能宣称方法已经迁移到真实WAM；
- 不能把高熵等同于完整多模态保存。
